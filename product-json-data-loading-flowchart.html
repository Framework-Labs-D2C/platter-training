Section 3: Data Merging Strategy

The ternary merge pattern used everywhere data is combined — full data always wins

// The merge pattern — used in getHtmlProduct, getCachedProduct, saveProduct
const merged = incoming._full_data
  ? incoming                    // Full incoming → use it
  : stored._full_data
    ? stored                  // Stored is full → keep it
    : incoming;                // Both partial → use latest
Rule 1

Full incoming wins

If the incoming data has _full_data: true, it always replaces whatever is stored — full data is the most complete source.

Rule 2

Full stored is protected

If stored data has _full_data: true but incoming doesn't, the stored version is kept. Partial never overwrites full.

Rule 3

Latest partial wins

When both incoming and stored are partial (no _full_data), the incoming (latest) data is used — it may have fresher prices or availability.

Section 6: Edge Cases & Notes

Important gotchas and implementation details developers should be aware of

No .catch() on Hydration Promise

The hydration promise in card_product_card.ts and main_product.ts has no error handler. If the network fetch fails, the product silently remains partial. The UI won't crash but will be incomplete.

PDP Inline JSON Only in Design Mode

Production PDP HTML has no [data-product-data] element. Inline JSON is only rendered when request.design_mode is true (Shopify theme editor). Production always relies on the fetch cascade.

Session Storage Optimization

sessionStorage.setItem(dbKey, "1") flags products that have full data cached in IDB. The data_product_json.liquid section checks this flag — if set, skips the preload link entirely, avoiding a redundant network request.

Recommendations Are Card Data

Related products returned from the /recommendations endpoint are loaded with card: true — they do not have _full_data. Each recommendation stores as partial data that will trigger its own hydration cascade when needed.

IDB Key Format Variants

Two key formats exist: _{themeId}-product--{handle} (product-data.ts) and _{themeId}-product--{handle}--{cacheVersion} (page-transitions.ts). The cache version suffix ensures stale data is invalidated on theme updates.

Fetch Priority Affects LCP

PDP uses priority: "high" so the product fetch competes with critical resources. Cards use "auto" (browser default), which defers to after layout-critical resources are loaded.

requestIdleCallback for IDB Writes

All IndexedDB writes go through requestIdleCallback with sequence tracking. This prevents IDB operations from blocking the main thread during interactive moments (scrolling, animations).

Barba Prefetch & handleRouteCaching

When Barba prefetches a page, handleRouteCaching extracts [data-product-data] from the prefetched HTML and stores it to IDB. This means the cascade may find data in IDB even on first SPA visit to a product.
