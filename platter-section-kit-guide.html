01

What the kit is

Reusable content blocks that slot into the body of a Vitamin Shoppe landing page, between the existing site header and footer (which the kit never touches).

Each section is a small self-contained component built to the TVS front-end standard: HTML + AlpineJS + a scoped <style> block, using the Lato brand font and no Tailwind. The product sections talk to TVS-Common (the site's shared micro-front-end, window._vsiMicroFE) to fetch live product data and add items to the real cart.

How a page is built: a landing page is a ct-landing-page content item that holds a sections[] list. Each entry in that list is one kit component (an Image Banner, a Product, or a Bundle). You order them top-to-bottom, fill each one's form, then publish the page. The URL is /lp/<deliveryKey>.

Because the data (what an author types) is stored separately from the template (the look), a marketer can build and re-arrange a whole page without a developer, and the same section can be reused across many pages with different content.

How to add a section to a landing page

For content authors, no code needed. In Amplience:

  1. Go to Content and open (or create) a Landing Page in the Web - LP Pages / Platter folder.
  2. In the page's Sections list, click + Add, then + Create new content.
  3. Pick the component type you want: Image Banner, Product (Add to Cart), or Product Bundle.
  4. Fill in the form fields (see the field reference below). Required fields are marked in the form.
  5. Click Save and give the item a clear name (e.g. LP Prime — Hero Banner) so it's easy to find later.
  6. Repeat for each section, and drag them into the order you want them to appear on the page.
  7. Save the landing page.
  8. Publish the page, and choose to publish linked dependencies so the sections go live too.
  9. Request a Fastly cache flush for the page path (or wait for the cache to expire).
  10. View it at /lp/<deliveryKey> on the site.
Tip: for the two product sections you only enter a SKU (and options). The product name, photo, price and rating are pulled in automatically when the page loads, so they stay correct even if the catalog changes.

05

Where the pieces live (for developers)

Templates (the view)

Published to the Content Hub at cdn.c1.amplience.net/c/vitaminshopdev/Platter* — PlatterImageBanner, PlatterProductATC, PlatterProductBundle.

Schemas

Development → Content type schemas: cs-image-banner, cs-product-atc, cs-product-bundle.

Content types

Development → Content types: the ct-* registrations that turn each schema into an authorable component.

Sections allow-list

The cs-landing-page schema's sections enum lists which components may be added to a landing page.

Delivery & route

A page's delivery key maps to the /lp/<key> route. Publish, then request a Fastly flush for it to appear.

Source of truth

Section code lives in /sections/*.html in the repo; node build.js produces the upload-ready templates in /dist/templates/.

06

Finding a SKU

Open the product's PDP (product detail page). The SKU is the last part of the URL — use it in uppercase.

…/p/german-creatine-unflavored-11-1-oz-powder/vs-8531  →  SKU is VS-8531

SKUs follow the pattern letters-alphanumerics, e.g. VS-8531, ANP-14589. If a SKU isn't found, that item is quietly skipped and the rest of the section still renders.

07

Do & don't

✓ Do

  • Write real headings and body text — it's read by search engines and screen readers.
  • Always fill image alt text for accessibility (ADA).
  • Reuse the same section across pages; just change the content.
  • Double-check SKUs on the live PDP before publishing.
  • Publish linked dependencies, then request the Fastly flush.

✕ Don't

  • Touch the site header or footer — the kit lives only in the page body.
  • Bake copy into images; keep text as real text for SEO and ADA.
  • Change the Alpine + scoped-CSS pattern or add Tailwind to a section.
  • Assume the discount % is charged — it's display only in Phase 1.
  • Expect changes to show instantly without a publish + cache flush.
